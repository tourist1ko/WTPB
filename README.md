# PB Rank 1.3.0, Railway

## Готово
/pb br сохранена.
/pb register name:ТОЧНОЕ НАЗВАНИЕ связывает Discord-сервер с названием полка.
/rank показывает PNG-таблицу. /rank page:2 открывает следующую страницу.
Сортировка: общий К/Д по убыванию, при равенстве winrate, затем ник для стабильного порядка.
Колонки: игрок, К/Д, winrate, уничтоженные танки, самолёты, бои.
К/Д = (танки + самолёты) / смерти. Ноль смертей при наличии киллов = бесконечность, 0/0 = 0.
Winrate = победы / (победы + поражения). Учитываются только бои с известным результатом.

## Автоматический сбор без ключа
По умолчанию используется публичный Tactical Replays: https://www.antoniocnz.com/en/wt.
Ключ WTApi и вход в игровой аккаунт не нужны. Дополнительная программа на ПК не нужна.
Бот раз в минуту проверяет список боёв по тегу зарегистрированного полка. Найденный бой загружает со страницы архива. Это сторонний публичный источник, не официальный API Gaijin.
В списке применяется точное сравнение полного тега с официальным профилем. Статистика берётся только со стороны этого полка, для участников Discord с серверным ником WarThunderNickname (Имя).
Принимаются realistic, явный winnerTeam и scoreboardConfidence=full. Неполные данные не применяются. Результат берётся из поля победителя, без догадок по количеству убийств.
Танки = groundKills, самолёты = kills из сырого итогового отчёта scene.players. В готовой визуальной scoreboard-таблице поле kills означает сумму, поэтому эта таблица не используется для разделения статистики.

На первом запуске, после перезапуска и затем раз в час проверяются доступные бои последних 24 часов. Между этими проверками сканируется первая страница полка. За один цикл скачивается до 5 новых отчётов с паузой между запросами, поэтому начальная загрузка может занять несколько минут. Сохраняются ETag списка и пауза после HTTP 429.
Полученный бой сначала записывается в очередь /data/rank.sqlite. При недоступности Discord очередь повторяется. Одинаковые hex и decimal ID одной сессии не учитываются повторно. Статистика сохраняется между перезапусками с прежним Volume.
/pb status доступен администратору и показывает состояние источника и очередь.
Если полк уже зарегистрирован старой версией, бот получает его тег из официального профиля. Повторная регистрация не требуется.

Проверено 20.10.2026: источник без авторизации вернул список 105HP и бой 4ad212e8001639a5, 105HP против TEHb, Арденны. Все 16 строк убийств самолётов, наземной техники, смертей и стороны совпали с финальным footer серверного повтора. Сквозная проверка из Node.js получила реальный отчёт, записала его в тестовую SQLite и подтвердила защиту от дублей. Discord-сопоставление проверено с тестовым участником tourist__ (Айбар). Деплой на вашем Railway и вход с вашим Discord-токеном в этой проверке не выполнялись.

Ограничения: бот зависит от доступности и полноты стороннего архива. Бой появится только после обработки источником. Ничьи и отчёты без явного победителя не учитываются. Автоматически проверяется окно 24 часа, вся история сезона не загружается. При отключении дольше суток старые пропуски могут остаться. Сохранённая статистика при этом не обнуляется.
Если структура сайта изменится или статистика неполная, бот выдаст ошибку в логах и повторит попытку, а не запишет выдуманный результат.

## Дополнительный источник WTApi
Интеграция v1.2.0 сохранена как вариант. Для её выбора нужны STATS_SOURCE=wtapi и WTAPI_KEY с доступом SQB. Документация: https://wtapi.dev/docs. Это необязательно для обычной установки v1.3.0.
При STATS_SOURCE=tactical (по умолчанию) ключ не используется и не передаётся публичному архиву.
/pb import по-прежнему принимает только нормализованный JSON по examples/battle.json, не файл .wrpl.

## Установка
1. Загрузить содержимое папки pb-rank в корень GitHub-репозитория. Railway использует Dockerfile.
2. Variables: DISCORD_TOKEN, GUILD_ID, DATA_DIR=/data. Для автосбора v1.3.0 дополнительных секретов не нужно.
3. Создать Railway Volume и смонтировать в /data. Без него статистика потеряется после пересоздания контейнера.
4. Discord Developer Portal → приложение → Bot → Privileged Gateway Intents → SERVER MEMBERS INTENT включить.
5. Бот должен быть приглашён со scopes bot и applications.commands. Разрешения: View Channels, Send Messages, Attach Files. Администратор боту не нужен.
6. Остановить старую копию, задеплоить эту. Одна реплика, один процесс, один файл SQLite.
7. Выполнить /pb register name:название. Команду и импорт может выполнять только пользователь с разрешением Administrator.
8. Проверить /pb status. Дождаться загрузки найденных боёв и открыть /rank. Ручной импорт остаётся доступен через /pb import.

## Привязка
Используется именно серверный nickname участника. Требуется формат WarThunderNickname (Имя).
Сопоставление WT-ника без учёта регистра, без частичных совпадений. Боты и ники без формата пропускаются.
Если два участника имеют одинаковый WT-ник, оба пропускаются до устранения конфликта.
В отчёте должны быть только реальные игроки зарегистрированного полка, участвовавшие в этом бою, до 8 человек. Другой полк отклоняется.
JSON должен содержать только PvP-киллы, без ботов. tankKills обозначает уничтожение наземной техники.
Победа/поражение относится к стороне зарегистрированного полка. Ничьи и неполные отчёты отклоняются.
ID боя должен быть стабильным и одинаковым для всех загрузок одного боя. Дубликаты не учитываются.
Учёт идёт только для подходящих участников на момент импорта. Если бой уже принят, повторный импорт после смены ника ничего не добавит.
Ушедший с сервера или убравший формат игрок скрывается из таблицы. История остаётся в базе и снова видна при возвращении того же Discord ID с тем же WT-ником.
Смена WT-ника создаёт отдельную историю. Перенос между аккаунтами автоматически не выполняется.
Одновременно на сервере допускается один полк. Перед привязкой другого выполните /pb unregister.

Автотесты локальные, используют также обезличенные в части Discord ID фикстуры двух реальных боёв. Отдельно проверено чтение живого публичного источника. Реальное подключение Discord и доступ из Railway требуют проверки после деплоя.

## Удаление старых команд
При запуске бот полностью заменяет список команд в GUILD_ID актуальными /pb и /rank. Старые подкоманды /pb также удаляются. Старые глобальные команды этого приложения удаляются на всех серверах. Команды других ботов не затрагиваются. Серверные команды в других серверах не затрагиваются.
Остановите прежнюю копию бота перед деплоем, иначе она может зарегистрировать старые команды снова. После строки Ready обновите Discord через Ctrl+R. Статистика SQLite при синхронизации команд не удаляется.

## Исправление SQLite / Volume
При запуске контейнер исправляет права записи в папке данных и существующих файлах SQLite, затем запускает бота под UID/GID 1000. База не удаляется. Данные остаются в прежнем rank.sqlite.
Обновите все файлы, включая Dockerfile и src/bootstrap.js. Очистите вручную заданную Start Command в Railway: используйте команду из Dockerfile, чтобы не пропустить bootstrap.
Сохраните прежний Volume, Mount Path=/data и DATA_DIR=/data. Не создавайте новый Volume вместо старого. Подготовка прав выполняется после подключения Volume.

## Доступ и отвязка
/pb register, /pb unregister и /pb import выполняются только пользователями с разрешением «Администратор». Одного «Управлять сервером» недостаточно. Проверка выполняется в обработчике команды. /rank и /pb br доступны участникам. /pb unregister снимает привязку, сохраняя историю полка. Повторная регистрация того же точного названия возвращает доступ к статистике. Регистрация проверяет существование полка по его полному названию на официальном сайте.

## Таблица и страницы
/rank использует оформление «Чистая таблица». Колонки: К/Д, WinRate, Танки (Убийство), Самолет (Убийство). Количество боёв отображается под ником. Под таблицей кнопки Назад, номер страницы и Далее. На странице до 15 игроков. Переключать страницы может автор вызова /rank. Другие участники могут открыть собственную таблицу. Кнопки работают после перезапуска бота. Смена привязанного полка требует заново вызвать /rank.

## Проверка существования полка
/pb register name:полное название запрашивает официальный профиль и проверяет совпадение имени. Названия без различия регистра и с лишними пробелами приводятся к имени из профиля. Код 404 означает «Полк с таким названием не найден». Недоступность сайта, тайм-аут, блокировка или неизвестная страница означают «Не удалось проверить полк». В обоих случаях новая привязка не сохраняется, старая остаётся. Для ручного ввода требуется полное название. Автоподсказки могут находить название и тег в справочнике и подставляют полное название. Ошибочные привязки старой версии можно убрать через /pb unregister. Проверка профиля подтверждает существование полка и сохраняет его тег. Для автоматического рейтинга используется отдельный публичный архив.

## Автоподсказки и один полк
Поле name команды /pb register показывает до 25 совпадений при вводе от двух символов. Выберите полк из выпадающего списка. Подсказки ищут по названию и тегу. Для полного поиска используется публичный сервис Thunderinsights, предложения кэшируются в Volume. Перед привязкой любое выбранное имя повторно проверяется на официальном сайте War Thunder.
Если Thunderinsights недоступен, подсказки ограничены локальным справочником и ранее найденными полками. В комплекте небольшой начальный справочник с официального рейтинга. Это не полный список всех полков. Во время подготовки сборки Thunderinsights возвращал 503, поэтому полный живой поиск не подтверждён. Полное название можно ввести вручную.
Регистрация второго полка отклоняется, пока администратор не выполнит /pb unregister. Команда /pb unregister не требует названия, снимает текущую привязку и сохраняет статистику. Повторная отвязка просто сообщает, что полк не привязан.

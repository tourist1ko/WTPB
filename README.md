# PB Rank 1.5.4

Лимит: 10 запросов за любые последние 60 секунд для каждого пользователя. Все команды /pb, /rank и кнопки страниц используют общий счётчик. Лимит действует и на администраторов. После превышения бот отвечает только пользователю с временем ожидания. Отклонённые из-за лимита попытки не продлевают ожидание. Автоподсказки при вводе не расходуют лимит. Счётчики хранятся в памяти и сбрасываются при перезапуске.

## Статистика за сезон
/rank показывает текущий сезон, определённый по официальному расписанию полковых боёв. Границы календарных дат учитываются по Москве, как в расписании БР.
На картинке показаны даты сезона. У каждого сезона отдельные результаты. При смене сезона старые данные сохраняются, новый рейтинг начинается отдельно.
До 8 игроков на странице, кнопки Назад и Далее, сквозная нумерация. Кнопки прежнего сезона предлагают открыть /rank заново.

При первом запуске /pb stat update загружает все доступные бои зарегистрированного полка за текущий сезон. Команда доступна администратору. Нужно сначала привязать полк и вручную добавить участников.
Обновление выполняется в фоне. Сообщение показывает поиск страниц, число найденных и обработанных ПБ, недоступные отчёты и дату первого найденного боя. Обновляется это же сообщение, без сообщений в канал.
Повторный вызов во время прогона показывает его текущий прогресс. Если прогон дольше срока действия ответа Discord, он продолжится: повтори /pb stat update для актуального сообщения.
Каждый отчёт и результат сохраняются в SQLite. При ошибках или перезапуске повтори команду: она продолжит сохранённую работу. HTTP 429 сохраняет требуемую источником паузу. Неполные отчёты не превращаются в нулевые результаты или поражения.
После завершения обычная /pb stat update проверяет только новые страницы до первой полностью известной страницы и повторяет недоступные отчёты. Обработанные бои и их результаты не сбрасываются. Счётчик прогресса не начинается с нуля.
Для намеренного полного поиска, например если в архив добавили старые бои: /pb stat update full:true. Сохранённые отчёты используются из базы, статистика повторно не начисляется.
После полного прогона автоматический сбор новых боёв продолжает обновлять текущий сезон. Участник получает результаты из сохранённых сезонных отчётов сразу при /pb stat addplayer. Повторный прогон после добавления не нужен: открой /rank. В ответе addplayer показано число учтённых боёв. Повторная addplayer для уже добавленного человека также дополнит данные из базы, не обращаясь к источнику и не удваивая результат.

Команда проверяет весь доступный список полка без ограничения 24 часами. Она зависит от полноты стороннего архива. Сообщение «Статистика обновлена» не гарантирует, что в архиве есть каждый сыгранный бой сезона.
Проверка источника 23.10.2026: для ┾105HP┿ список содержал 234 боя, самые ранние доступные датированы 03.10.2026, хотя текущий сезон по официальному расписанию 01.09.2026–31.10.2026. Отсутствующие в источнике сентябрьские бои автоматически восстановить нельзя.

## Обновление
Останови старый процесс. Сохрани .env и storage либо прежний Railway Volume /data. Обнови файлы, запусти одну копию и дождись Ready.
Ручные участники и привязка полка сохраняются. Выполни /pb stat update, затем /rank.
Прежние общие суммы 1.3/1.4 не удаляются из базы. Они не подставляются в сезонный рейтинг: по общим числам нельзя достоверно определить даты отдельных боёв. Сезонные суммы строятся по отчётам с известной датой, включая бои, уже отмеченные в старой базе. Это также позволяет учесть участников, пропущенных старой версией, если полный отчёт есть в источнике.
Если список участников ещё пуст, сначала добавь каждого вручную. Пропущенные в архиве бои не выдумываются.

## Участники только вручную
/pb stat addplayer nickname:@участник
В nickname выбери человека из Discord. Если серверный ник tourist__ (Айбар), будет сохранён tourist__. Без скобок берётся весь серверный ник, без серверного ника берётся username.
Если игровой ник отличается:
/pb stat addplayer nickname:@участник wtnick:tourist__
/pb stat removeplayer nickname:@участник убирает из текущего списка, сохраняя историю.
/pb stat list показывает весь добавленный список.
Все команды группы stat доступны только администратору. Автоматического добавления по никам нет. Смена ника или выход из Discord не меняют сохранённую привязку. Удаление выполняется вручную.
Один игровой ник нельзя одновременно привязать к двум участникам. Для смены привязки сначала removeplayer, затем addplayer. У нового игрового ника отдельная история.

## Рейтинг
Сортировка: К/Д по убыванию, затем WinRate, затем ник для стабильного порядка.
К/Д = (убийства танков + убийства самолётов) / смерти самого игрока. При убийствах без смертей показывается бесконечность, без боёв К/Д и WinRate равны нулю.
WinRate = победы / (победы + поражения). Колонки: Игрок, К/Д, WinRate, Танки (Убийство), Самолет (Убийство). Число боёв показано под ником.
Шрифты включены в assets/fonts. Листать таблицу может автор вызова, другие участники могут открыть собственную /rank.

## Полк и источник
/pb register name:полное название проверяет существование полка на официальном сайте и сохраняет его полный тег. На сервере один полк.
/pb unregister снимает привязку, сохраняя историю полка, сезонные данные и ручной список.
/pb br показывает две строки: Қәзіргі БР - 6.0 и Келесі БР - 5.0 (27.10.2026). Значения и дата смены берутся из официального расписания. Если следующий БР ещё не опубликован, вторая строка: Келесі БР - жарияланбаған. Дата в примере соответствует проверке 23.10.2026.
/pb status показывает состояние автоматического сбора и сезонного обновления.
/pb import report:файл принимает нормализованный JSON по examples/battle.json, не .wrpl. Для сезонного учёта обязательно поле playedAt с датой начала боя в ISO 8601, включая время и часовой пояс, например 2026-10-20T12:00:00Z.
/pb register, unregister, import, status и stat доступны администратору. /rank и /pb br доступны участникам.

По умолчанию STATS_SOURCE=tactical, публичный архив https://www.antoniocnz.com/en/wt, без ключа и игрового аккаунта. Обычный автосбор раз в минуту проверяет новые бои, после запуска и раз в час — доступные последние 24 часа. /pb stat update дополнительно проверяет весь сезон.
Применяются полные realistic-отчёты с явным победителем, точным полным тегом и согласованными итогами убийств. Танки = groundKills, самолёты = kills из сырых scene.players. Ничьи и отчёты без подтверждённого результата не учитываются.
Сборщик не сканирует список Discord. Server Members Intent не нужен. При addplayer проверяется только выбранный участник.
Необязательный STATS_SOURCE=wtapi требует WTAPI_KEY с SQB-доступом. Полный сезонный прогон использует публичный архив и при этом режиме. Ключ ему не передаётся.

## Запуск Railway
Файлы в корень репозитория. Dockerfile включён. Variables: DISCORD_TOKEN, GUILD_ID, DATA_DIR=/data, STATS_SOURCE=tactical. Подключи прежний Volume к /data.
Одна реплика, один процесс и один SQLite. Docker исправляет права Volume без удаления базы и понижает UID/GID.
Приглашение бота: scopes bot, applications.commands. Права View Channels, Send Messages, Attach Files. Администратор самому боту не нужен.
При запуске актуальные команды заменяют прежние команды этого приложения. После Ready при необходимости обнови Discord Ctrl+R.
